# Azure GPT-4o Vision Chat and SVG Art Studio

An image-understanding chatbot and a text-to-image generator built on a single GPT-4o deployment in Microsoft Azure AI Foundry. Images are generated without a dedicated image-generation model: GPT-4o produces them as SVG vector code.

## Overview

The project contains two Streamlit applications that share the same GPT-4o deployment.

| Application | File | Description |
|---|---|---|
| Image Explainer Chatbot | `apps/image_chatbot.py` | Upload an image and ask questions about it. The model describes and analyzes the image and keeps the conversation context across turns. |
| SVG Art Studio | `apps/svg_image_maker.py` | Describe an image in plain language. The model returns SVG code, which is rendered in the browser, can be refined with follow-up prompts, and exported as SVG or PNG. |

## How image generation works

Instead of calling an image model such as DALL·E or Stable Diffusion, the application uses GPT-4o to write the image as code:

```
Prompt  ->  GPT-4o  ->  SVG code  ->  Rendered in browser  ->  SVG / PNG download
```

1. A system prompt instructs the model to respond only with a complete SVG document built from shapes, paths and gradients.
2. The application extracts the `<svg>` element from the response and rejects any output containing scripts or event handlers.
3. The SVG is displayed and offered for download. If CairoSVG is available, it is also converted to a 1024 px PNG.
4. Follow-up prompts include the current SVG, so the model edits the existing image rather than starting over.

**Advantages of this approach**

- **Lower cost:** reuses the existing chat deployment; no separate image model is required.
- **Resolution-independent:** vector output scales to any size without loss of quality.
- **Editable:** the result is plain code that can be refined iteratively or edited by hand.

## Features

**Image Explainer Chatbot**
- Supports PNG, JPG, JPEG and WEBP uploads
- Multi-turn conversation memory using the Responses API (`previous_response_id`)
- Works as a general-purpose assistant when no image is provided
- Option to clear the conversation

**SVG Art Studio**
- Text-to-image generation through SVG code
- Iterative editing of the current image
- Basic safety filtering of generated SVG
- Export as SVG or PNG

## Getting started

### Prerequisites

- Python 3.10 or later
- An Azure AI Foundry resource with a GPT-4o deployment
- Optional, for PNG export: the [Cairo graphics library](https://cairosvg.org/documentation/#installation)

### 1. Clone the repository

```bash
git clone https://github.com/marriyamjamil/azure-gpt4o-vision-chat-svg-art.git
cd azure-gpt4o-vision-chat-svg-art
```

### 2. Create a virtual environment and install dependencies

```bash
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS / Linux
pip install -r requirements.txt
```

### 3. Configure environment variables

Copy `.env.example` to `.env` and provide your values:

```env
AZURE_OPENAI_BASE_URL=https://<your-resource-name>.services.ai.azure.com/openai/v1/
AZURE_OPENAI_API_KEY=<your-api-key>
CHAT_DEPLOYMENT=<your-gpt-4o-deployment-name>
```

| Variable | Description |
|---|---|
| `AZURE_OPENAI_BASE_URL` | Azure AI Foundry OpenAI v1 endpoint |
| `AZURE_OPENAI_API_KEY` | API key for the Azure resource |
| `CHAT_DEPLOYMENT` | Deployment name of the GPT-4o model |

### 4. Run the applications

```bash
streamlit run apps/image_chatbot.py
```

```bash
streamlit run apps/svg_image_maker.py
```

## Deployment to Azure App Service

1. Create an Azure App Service (Linux, Python 3.10 or later) and deploy this repository to it.
2. Under **Settings > Environment variables > App settings**, add `AZURE_OPENAI_BASE_URL`, `AZURE_OPENAI_API_KEY` and `CHAT_DEPLOYMENT`.
3. Under **Configuration > Startup command**, set:

   ```bash
   python -m streamlit run apps/image_chatbot.py --server.port 8000 --server.address 0.0.0.0
   ```

   To deploy the SVG Art Studio instead, replace the path with `apps/svg_image_maker.py`.

> **Note:** PNG export depends on the Cairo system library, which may not be available on the App Service host. If it is missing, the application displays a warning and SVG export continues to work.

## Security

- `.env` is excluded through `.gitignore`, so credentials are never committed. In Azure, they are stored as App Settings.
- Generated SVG is checked for `<script>`, `onload=` and `onclick=` before rendering.
